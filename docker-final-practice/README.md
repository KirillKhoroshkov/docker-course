### В соответствии с бизнес-задачей система состоит из таких компонентов:

1. Сервер сжатия изображений. Считается, что новые документы могут загружаться относительно редко, а большие объёмы
   существующих данных можно загружать в пакетном режиме. Этот сервис разрабатывался на Python.
1. Сервис раздачи сжатых изображений. Этой частью системы будут пользоваться все сотрудники организации. Сервис должен
   показывать высокую производительность и поддерживать масштабирование. Он разработан на языке Go и должен быть
   простым, быстрым и нетребовательным.
1. Балансировщик нагрузки, распределяющий запросы на загрузку и отдачу документов.

#### В репозитории уже находится код двух серверных приложений.

1. Написанное на Python приложение image-compress. Это HTTP-сервер для сжатия картинок; он принимает файл в
   POST-запросе, уменьшает в заданное количество раз и сохраняет в каталоге (по умолчанию - /tmp). Путь для сохранения
   можно поменять, указав его в переменной окружения IMAGE_PATH. С помощью переменной окружения COMPRESS_RATIO можно
   установить степень сжатия картинки. Сервер будет уменьшать её линейные размеры во столько раз, сколько указано в
   значении этой переменной.
1. Приложение image-serve написано на Go. Это HTTP-сервер для обслуживания запросов на получение файлов. Имя каталога, в
   котором он будет искать файлы, можно задать аргументом командной строки image_path (по умолчанию это /data/images/).

Вам нужно будет научиться запускать эти приложения так, чтобы они работали совместно: image-compress принимал запросы на
сжатие файлов и сохранял их на внешнем томе, а image-serve отдавал эти сжатые картинки по запросу. Для этого они должны
совместно использовать один и тот же том.
Запросы к приложениям должны проходить через прокси-сервер nginx. Конфигурационный файл nginx также содержится в
репозитории в каталоге proxy.
